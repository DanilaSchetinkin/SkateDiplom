РАЗДЕЛ 1.5.9 ReactiveUI / CommunityToolkit.MVVM
-----------------------------------------------------------------
ЗАМЕНИТЬ ТЕКСТ:

Для реализации паттерна MVVM был выбран пакет ReactiveUI (Avalonia.ReactiveUI). 
Данное решение было принято как стандартное для Avalonia UI и обеспечивает 
реактивное программирование с автоматическим обновлением интерфейса. 
ReactiveUI предоставляет базовый класс ReactiveObject для ViewModel, 
систему команд через ReactiveCommand и механизм подписки на изменения свойств. 
Это позволяет создавать отзывчивые интерфейсы с минимальным количеством кода.

РАЗДЕЛ 2.2.1 Описание функциональности
-----------------------------------------------------------------
ОБНОВИТЬ текст, добавив информацию о трех типах пользователей:

Функциональная диаграмма (Рисунок 3), выполненная в методологии SADT, 
представляет систему управления контентом как сложный преобразователь, 
который под управлением определенных правил и с использованием конкретных 
механизмов преобразует входные потоки данных в выходные результаты.

Центральный блок диаграммы "Управление интернет-магазином скейтбординга" 
является ядром системы, которое получает на вход потоки данных от трех 
типов пользователей:

1. КЛИЕНТЫ передают:
   - Запросы на просмотр каталога товаров
   - Выбор товаров и добавление в корзину
   - Данные для оформления заказов
   - Обращения в службу поддержки

2. СОТРУДНИКИ передают:
   - Изменения статусов заказов
   - Обращения в техническую поддержку

3. АДМИНИСТРАТОРЫ передают:
   - Данные о товарах с изображениями
   - Управление пользователями
   - Ответы на обращения в поддержку
   - Запросы на формирование отчетов

Сверху на центральный блок оказывают управляющее воздействие:
- Бизнес-правила магазина (политика ценообразования, система скидок)
- Требования администратора (регламенты обработки заказов)
- Законодательные нормы (защита персональных данных, налоговое законодательство)

Снизу центральный блок поддерживается механизмами реализации:
- База данных PostgreSQL с асинхронным доступом через Entity Framework Core
- Desktop-приложение на платформе Avalonia с ReactiveUI
- Система ролевого доступа (клиент/сотрудник/администратор)
- Система обмена сообщениями для поддержки

На выходе система производит:
- Управляемый каталог товаров с изображениями и категориями
- Обработанные заказы с автоматической генерацией номеров
- Удовлетворенные клиенты с историей покупок
- Оперативные данные о состоянии магазина

РАЗДЕЛ 2.7 Инструкция пользователя
-----------------------------------------------------------------
ПОЛНОСТЬЮ ПЕРЕПИСАТЬ раздел 2.7, так как текущее описание не соответствует 
реальному интерфейсу. Вот обновленная структура:

2.7 Инструкция пользователя

Система управления интернет-магазином скейтбординга SkatePro предоставляет 
три типа интерфейсов в зависимости от роли пользователя: клиент, сотрудник 
и администратор.

2.7.1 Окно входа в систему

Главное окно приложения (MainWindow) предоставляет форму авторизации с полями:
- Email пользователя
- Пароль
- Кнопка "Войти"

После успешной авторизации система определяет роль пользователя и открывает 
соответствующий интерфейс.

2.7.2 Интерфейс клиента (ClientWindow)

Окно клиента содержит верхнюю панель навигации с кнопками:
- Каталог - просмотр товаров
- Корзина - управление выбранными товарами
- Мои заказы - история покупок
- Поддержка - обращение в службу поддержки
- Выход - завершение сеанса

В верхней части отображается ФИО клиента.

КАТАЛОГ ТОВАРОВ (ClientCatalogView):
- Горизонтальная панель с кнопками категорий (Все товары, Деки, Колеса и т.д.)
- Активная категория выделена цветом (#4F52A0)
- Поле поиска по названию товара
- Выпадающий список сортировки (по названию, по цене)
- Сетка товаров с карточками, содержащими:
  * Изображение товара
  * Название и артикул
  * Бренд и категория
  * Цена
  * Остаток на складе
  * Кнопка "В корзину"

КОРЗИНА (CartView):
- Список добавленных товаров с изображениями
- Для каждого товара:
  * Изображение
  * Название и цена
  * Поле изменения количества (NumericUpDown, ширина 120px)
  * Кнопка удаления
- Общая сумма заказа
- Поле для комментария к заказу
- Кнопка "Оформить заказ"

При добавлении товара из каталога корзина автоматически обновляется 
благодаря событию CartChanged.

МОИ ЗАКАЗЫ (ClientOrdersView):
- Список заказов клиента с информацией:
  * Номер заказа (формат ORD-YYYYMMDD-XXXX)
  * Дата создания
  * Статус (новый, в обработке, отправлен, доставлен, отменен)
  * Общая сумма

ПОДДЕРЖКА (ChatView):
- История сообщений с администратором
- Поле ввода нового сообщения
- Кнопка отправки
- Сообщения отображаются с указанием отправителя и времени
- Автоматическое создание беседы при первом обращении

2.7.3 Интерфейс администратора и сотрудника (Admin)

Окно администратора/сотрудника содержит:
- Верхняя панель с ФИО и ролью пользователя
- Боковая панель навигации с кнопками:
  * Товары (только для администраторов)
  * Заказы
  * Пользователи (только для администраторов)
  * Обращения клиентов (только для администраторов)
  * Обращения сотрудников (только для администраторов)
  * Техподдержка (только для сотрудников)
  * Выход

Видимость кнопок настраивается методом SetupInterfaceForRole в зависимости 
от роли пользователя.

УПРАВЛЕНИЕ ТОВАРАМИ (ProductsView) - только администраторы:
- Список всех товаров в табличном виде
- Кнопка "Добавить товар"
- Для каждого товара кнопки редактирования и удаления
- При редактировании открывается окно ProductEditorWindow с полями:
  * Артикул (SKU)
  * Название
  * Описание
  * Цена
  * Количество на складе
  * Выбор категории
  * Выбор бренда
  * Кнопка выбора изображения
  * Предпросмотр изображения
  * Кнопки "Сохранить" и "Отмена"

Изображения сохраняются в папку ProductImages с уникальными именами (GUID).

УПРАВЛЕНИЕ ЗАКАЗАМИ (OrderView):
- Список всех заказов с информацией:
  * Номер заказа
  * Имя клиента
  * Дата создания
  * Общая сумма
  * Выпадающий список для изменения статуса
- Двойной клик открывает окно OrderDetailsWindow с детальной информацией:
  * Полные данные заказа
  * Список товаров в заказе
  * Контактная информация клиента

УПРАВЛЕНИЕ ПОЛЬЗОВАТЕЛЯМИ (UserView) - только администраторы:
- Список всех пользователей системы
- Возможность редактирования данных пользователей
- Назначение ролей (клиент, сотрудник, администратор)

ОБРАЩЕНИЯ КЛИЕНТОВ (SupportInboxView) - только администраторы:
- Список всех обращений клиентов в поддержку
- Клик по обращению открывает чат с клиентом
- Администратор автоматически добавляется в беседу

ОБРАЩЕНИЯ СОТРУДНИКОВ (SupportInboxView) - только администраторы:
- Список обращений сотрудников в техподдержку
- Аналогично обращениям клиентов

ТЕХПОДДЕРЖКА (ChatView) - только сотрудники:
- Чат с администраторами для получения технической помощи
- Автоматическое создание беседы при первом обращении

2.7.4 Особенности работы системы

АВТОМАТИЧЕСКОЕ ОБНОВЛЕНИЕ:
- Корзина обновляется автоматически при добавлении товаров из каталога
- Используется событийная модель (CartChanged)

РАБОТА С ИЗОБРАЖЕНИЯМИ:
- Изображения товаров загружаются из папки ProductImages
- Конвертер FilePathToBitmapConverter автоматически ищет файлы в нескольких папках
- Поддерживаются форматы: JPG, PNG, BMP

АСИНХРОННАЯ РАБОТА:
- Все операции с базой данных выполняются асинхронно
- Интерфейс остается отзывчивым во время загрузки данных
- Используется Dispatcher.UIThread.InvokeAsync для обновления UI

СИСТЕМА ЧАТ-ПОДДЕРЖКИ:
- Для каждого клиента создается одна беседа с поддержкой
- Для каждого сотрудника создается одна беседа с техподдержкой
- История сообщений сохраняется в базе данных
- Сообщения отображаются в хронологическом порядке
